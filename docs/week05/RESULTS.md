## A tour of the packets

### A participant announces itself

SPDP, sent to the multicast group 239.255.0.1 on port 7400 (domain 0). It says who this participant is (its GUID prefix and vendor), where to reach it (unicast locators), which builtin endpoints it has, and how long to consider it alive (the lease). ROS 2 adds the enclave in the user data.

`127.0.0.1:33317` to `239.255.0.1:7400` (domain 0 discovery multicast): SPDP: participant 010feb7d (eProsima Fast DDS) at udpv4:172.17.0.2:7411

### The talker announces its publisher

SEDP, sent reliably to each participant that SPDP found. The topic is rt/topic (ROS 2 prefixes rt/ to every topic), the type is std_msgs::msg::dds_::String_, the QoS is reliable and volatile, and Jazzy adds the REP 2011 type hash in the user data.

`127.0.0.1:33317` to `127.0.0.1:7412` (domain 0 participant 1 discovery unicast): SEDP: publication ros_discovery_info [rmw_dds_common/msg/ParticipantEntitiesInfo] reliable, transient_local; SEDP: publication rt/rosout [rcl_interfaces/msg/Log] reliable, transient_local; SEDP: publication rt/parameter_events [rcl_interfaces/msg/ParameterEvent] reliable, volatile; SEDP: publication rr/minimal_publisher/describe_parametersReply [rcl_interfaces/srv/DescribeParameters_Response] reliable, volatile; SEDP: publication rr/minimal_publisher/get_parametersReply [rcl_interfaces/srv/GetParameters_Response] reliable, volatile; SEDP: publication rr/minimal_publisher/get_parameter_typesReply [rcl_interfaces/srv/GetParameterTypes_Response] reliable, volatile; SEDP: publication rr/minimal_publisher/list_parametersReply [rcl_interfaces/srv/ListParameters_Response] reliable, volatile; SEDP: publication rr/minimal_publisher/set_parametersReply [rcl_interfaces/srv/SetParameters_Response] reliable, volatile; SEDP: publication rr/minimal_publisher/set_parameters_atomicallyReply [rcl_interfaces/srv/SetParametersAtomically_Response] reliable, volatile; SEDP: publication rr/minimal_publisher/get_type_descriptionReply [type_description_interfaces/srv/GetTypeDescription_Response] reliable, volatile; SEDP: publication rt/topic [std_msgs/msg/String] reliable, volatile

### Hello World on the wire

A DATA submessage carrying one sample. INFO_DST says which participant it is for, INFO_TS when it was written. The payload is CDR: 00 01 00 00 (little endian, plain CDR), a uint32 length that counts the terminating NUL, then the characters.

`127.0.0.1:33317` to `127.0.0.1:7413` (domain 0 participant 1 user unicast): DATA std_msgs/msg/String #6: {'data': 'Hello World: 5'}

### The writer: 'I have samples first to last'

Reliable delivery is a conversation. The writer's HEARTBEAT lists the sequence numbers it still holds; a reader that is missing any asks for them.

`127.0.0.1:33317` to `127.0.0.1:7413` (domain 0 participant 1 user unicast): HEARTBEAT user writer 0x13 has [6, 5]

### The reader: 'I have everything below base'

The ACKNACK answers with a sequence number set: everything below the base has arrived, and the bitmap lists what is missing. An empty set is a pure acknowledgement.

`127.0.0.1:52700` to `127.0.0.1:7411` (domain 0 participant 0 user unicast): ACKNACK user reader 0x13: have everything below 6

### A service request

Services are two topics: rq/add_two_intsRequest and rr/add_two_intsReply. The request carries a RELATED_SAMPLE_IDENTITY naming the client's reply reader, twice: in the standard parameter (0x0083) and in Fast DDS's own (0x800f).

`127.0.0.1:42638` to `127.0.0.1:7411` (domain 0 participant 0 user unicast): DATA example_interfaces/srv/AddTwoInts_Request #1: {'a': 2, 'b': 3}

### Its reply

The reply quotes the same identity with the request's sequence number filled in, which is how the client matches it to the request it sent.

`127.0.0.1:54557` to `127.0.0.1:7413` (domain 0 participant 1 user unicast): DATA example_interfaces/srv/AddTwoInts_Response #1: {'sum': 5}
